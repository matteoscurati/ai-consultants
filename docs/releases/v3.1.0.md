# Release v3.1.0

**Date:** 2026-07-24
**Type:** Minor — Grok 4.5 becomes a secure CLI-first consultant through Grok Build
**Previous:** v3.0.0

## Highlights

- **Grok 4.5 now uses the official Grok Build CLI by default**, including OAuth/subscription authentication already available on the machine.
- **Each Grok consultation runs in an isolated, tool-free environment** without importing local plugins, hooks, MCP servers, skills, memories, or project instructions.
- **The xAI API remains available as a focused fallback** when Grok Build is missing, cannot launch, or is not authenticated.
- **CLI request failures never silently become billable API requests.** Timeouts, model errors, and empty responses are returned as failures on the attempted CLI transport.
- **Large contexts are safe from shell argument limits** because prompts are delivered through a private file instead of the process command line.

## What's New

### Grok Build CLI transport

Grok joins the CLI-first consultant roster with `grok-4.5` pinned explicitly. Existing installations prefer the `grok` command; API-only installations continue to use the xAI Chat Completions transport when `GROK_API_KEY` or `XAI_API_KEY` is configured.

Every response records the route that answered:

| `metadata.transport` | Meaning |
|---|---|
| `cli` | Grok Build answered |
| `api` | API mode was explicitly selected |
| `api_fallback` | The CLI was unavailable and the xAI API answered |

### Isolated advisory execution

AI Consultants uses Grok as an advisory model, not as an editing agent. The adapter therefore starts Grok Build with:

- an ephemeral HOME and empty working directory;
- no built-in tools, MCP tools, subagents, memory, or web access;
- fail-closed permissions and the strict sandbox;
- only the existing Grok authentication material copied into the private runtime;
- automatic cleanup after the response.

The consultation receives only the prompt and context explicitly assembled by AI Consultants.

### Narrow API fallback

The API fallback is limited to transport availability:

- Grok Build is not installed;
- the command cannot execute or launch;
- the CLI has no usable authentication.

Failures after the CLI request starts—including timeouts, model errors, and empty output—are surfaced directly. This prevents a broken CLI request from silently producing a separate API charge.

### Private prompt files

The complete prompt is written to a mode-600 temporary file and passed with `--prompt-file`. This keeps prompt content out of process listings and supports contexts larger than the operating system's argument-vector limit.

## Breaking Changes

None — this release is backwards-compatible. `GROK_USE_API=true` still forces the API transport, and the existing `GROK_API_KEY` configuration remains supported.

## Upgrade Guide

```bash
# If installed via git clone
cd ~/.claude/skills/ai-consultants && git pull

# If installed via curl | bash
curl -fsSL https://raw.githubusercontent.com/matteoscurati/ai-consultants/main/scripts/install.sh | bash

# If used through npx
npx ai-consultants@latest "your question"
```

Install and authenticate Grok Build to use the new default transport:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login
```

No configuration changes are required. Systems without a usable Grok Build CLI continue to use the configured xAI API fallback.
