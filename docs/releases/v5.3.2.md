# Release v5.3.2

**Date:** 2026-10-21
**Type:** Patch — no more copies of your files in the cache; clearer Coverage Union; a test guard against broken jq filters
**Previous:** v5.3.1

## Highlights

- **Your files are no longer copied into the cache.** Context chunking saved every large file it processed to `~/.cache/ai-consultants/chunks` and never removed it. Chunks now stay in memory.
- **The report says why there is no Coverage Union.** It names the strategy that doesn't produce one, an empty union, or the exact jq error, instead of one generic "coverage data unavailable".
- **The test gate fails on any jq filter that cannot compile**, even one whose error the code discards. That class of bug hid the Coverage Union until 5.3.1.

## What's New

### No copies of project files in the cache

When a file was large enough to be chunked, `chunk_file_semantically` wrote the chunks (your code, as JSON) to `CHUNK_TEMP_DIR/<session>_chunks.json`. Nothing read that file and nothing deleted it, so copies piled up across runs: 437 files since May on one maintainer machine. The chunks are still built and used the same way, but only in memory. `CHUNK_TEMP_DIR` is still accepted and is now unused.

Copies written by earlier versions are not deleted automatically. To remove them:

```bash
rm -rf ~/.cache/ai-consultants/chunks
```

### Coverage Union: say which case it is

`report.md` now distinguishes three cases:

| Situation | Report line |
|---|---|
| The strategy does not merge a union (for example `majority`) | "the majority strategy does not produce a coverage union" |
| The coverage synthesis returned no points | "the synthesis returned no coverage points" |
| `synthesis.json` cannot be read | the jq error itself, also logged as a warning |

### jq compile-error guard

`npm test` runs every suite with a jq shim first on PATH. The shim passes input, output and exit codes through unchanged. It records any compile error, even when the caller discards stderr with `2>/dev/null`, and the run fails if anything was recorded. Runtime errors, such as invalid JSON input, are left to the code that handles them.

With the 5.3.0 code, the guard records three errors from the synthesis tests alone. A sweep of the current suite found none. jq 1.7.1 also rejects the old filter, so the Coverage Union never rendered on any jq version before 5.3.1.

## Breaking Changes

None — this release is backwards-compatible.

## Upgrade Guide

```bash
# npx (no install)
npx ai-consultants "question"

# git clone install
cd ~/.claude/skills/ai-consultants && git pull

# curl | bash install
curl -fsSL https://raw.githubusercontent.com/reasance/ai-consultants/main/scripts/install.sh | bash
```

No configuration changes required. Optionally remove old chunk copies with `rm -rf ~/.cache/ai-consultants/chunks`.
