# Release v4.0.2

**Date:** 2026-08-28

**Type:** Patch — concurrency-safe Grok OAuth

**Previous:** v4.0.1

## Highlights

- Parallel Grok Build consultations can now share rotating OAuth safely without sharing agent state.
- Refreshed credentials survive temporary HOME cleanup and are published atomically to the ambient session.
- A concurrent external `grok login` always wins; the affected consultation fails without overwriting it or creating an API charge.
- A real two-process `grok-4.6` smoke returned two structured `PONG` responses with exit 0.

## What's New

### Shared OAuth by default

`GROK_OAUTH_MODE=shared` is now the normal Grok CLI path. The runner maintains one persistent credential generation under:

```text
$XDG_DATA_HOME/ai-consultants/grok-shared-oauth
```

Only `GROK_HOME` is shared. Each consultation still receives an independent HOME, workspace, private prompt, output, capability-probe environment, strict sandbox, empty tool surface, model, and effort.

Grok Build's own auth lock coordinates token refresh between concurrent processes. The ai-consultants lock is used only for bounded seed, first-use bootstrap, authenticated inventory, and publication — never for inference.

### Atomic refresh publication and CAS

The shared marker binds the active generation to the SHA-256 of the credential last synchronized with ambient `~/.grok/auth.json`.

After a run:

- unchanged valid credentials require no write;
- a valid rotation is copied into a mode-600 candidate and atomically renamed;
- malformed rotation fails closed;
- a changed ambient digest means an external login won, so the run fails temporarily and publishes no successful answer;
- a publication failure never triggers the separately billed xAI API fallback.

`GROK_OAUTH_MODE=serialized` remains available for diagnostic comparison and holds the runner lock across the complete CLI call.

### Provider-owned configuration

Grok 1.0.4 lazily creates provider-required metadata, caches, DBs, and `config.toml`. ai-consultants therefore preserves that file and stores its own atomic contract in `.ai-consultants-policy.json`. The effective agent restrictions remain pinned through the invocation arguments.

Generations produced by the earlier development runner are recognized from their exact legacy config signature and superseded without deletion or mutation.

### Sanitized failures

Grok requests use redacted retry logging. Token-shaped provider stderr remains only in ephemeral private storage and never reaches argv, stdout, logs, error envelopes, or consultation artifacts.

## Breaking Changes

None. `shared` replaces the unsafe disposable-copy behavior for CLI OAuth, but model, effort, permissions, sandbox, response schema, API transport, and fallback classification remain unchanged.

Users who need full-run serialization for diagnosis can set:

```bash
GROK_OAUTH_MODE=serialized
```
