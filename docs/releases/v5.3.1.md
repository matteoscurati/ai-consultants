# Release v5.3.1

**Date:** 2026-10-21
**Type:** Patch — `report.md` shows the merged Coverage Union points again; Ctrl-C reports stopped consultants correctly
**Previous:** v5.3.0

## Highlights

- **`report.md` lists every merged point again.** Under "Coverage Union", each point now prints with its kind and the consultants that raised it. With jq 1.8 the section always read "coverage data unavailable", even when the synthesis held the points.
- **A terminal Ctrl-C no longer reports a consultant it stopped as failed.** The run now records it as stopped, whenever in the polling pass the interrupt lands.
- **The README states what the panel has and hasn't shown.** It no longer says the merged list "covers what any one misses". It reports the small internal test behind the breadth claim and its limits.
- **The MiniMax API transport is verified live.** One API call to MiniMax-M3.1-Flash returned a structured answer with a provider-reported model identity.

## What's New

### Coverage Union in report.md

The coverage strategy (the default) merges every distinct point from the panel into `synthesis.json` and audits that each one is cited. The report then renders that list under "Coverage Union". The jq filter that rendered it escaped its quotes inside a string interpolation. jq 1.8 rejects that as a syntax error, and the error was silenced. The section therefore fell back to "coverage data unavailable" on every run, while Coverage Integrity, the recommendation and the risk table above it were correct.

The filter now uses plain quotes. A regression test runs a whole consultation with a stub synthesis and checks the rendered line:

```
- **risk**: Retries need idempotency keys — raised by Claude, Mistral
```

The bug turned up while recording the demo for aiconsultants.sh. A real 5.3.0 run reported `MET (37/37 normalized source IDs represented)` with 26 merged points in `synthesis.json`, and none of them reached the report.

### Ctrl-C and stopped consultants

A first Ctrl-C tells the run to continue with the answers it has; the consultants still running are stopped and reported as `stopped`. The interrupt reaches the consultant CLIs at the same moment. If it landed after the run had checked for host requests in its current polling pass, a consultant whose CLI it had just ended could finish within that pass and be reported as failed (`Error (code: 1)`). It is now reported as stopped. This race also made the end-to-end Ctrl-C test flaky on slower CI runners.

### Documentation

The README "Why AI Consultants?" section now says that different model families *often* raise different points. In one small internal test with three open-ended tasks, the merged list covered more items on a reference checklist than one strong model alone, or one model sampled several times. The README calls that a direction, not a benchmark, and says there is no evidence that a panel is more accurate than one strong model.

### Verification

- Offline gate: 34/34 suites, lint and the generated-docs check, locally, in PR #32 CI and in the release gate.
- The Ctrl-C race was reproduced in a scratch copy by moving the interrupt into the window between the host check and collection: the old loop failed the assertion 3 times out of 3, the new one passed 3 times out of 3.
- MiniMax API smoke (2026-10-20, after the 5.3.0 release): HTTP 200, structured answer, provider-reported `MiniMax-M3.1-Flash`. 5.3.0 had shipped with the API path tested offline only.

## Breaking Changes

None — this release is backwards-compatible.

## Upgrade Guide

```bash
# npx (no install)
npx ai-consultants "question"

# git clone install
cd ~/.claude/skills/ai-consultants && git pull

# curl | bash install
curl -fsSL https://raw.githubusercontent.com/matteoscurati/ai-consultants/main/scripts/install.sh | bash
```

No configuration changes required. Reports written before this release are not rewritten. Each run's merged points are still in its `synthesis.json`:

```bash
jq -r '.coverage[] | "- \(.kind): \(.point) [\(.raised_by | join(", "))]"' synthesis.json
```
