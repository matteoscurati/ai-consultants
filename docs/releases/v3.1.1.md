# Release v3.1.1

**Date:** 2026-07-24
**Type:** Patch — complete doctor diagnostics when a consultant is unavailable
**Previous:** v3.1.0

## Highlights

- **`doctor` now reaches its final summary when an enabled CLI is missing.**
- **JSON diagnostics always emit a complete object before returning unhealthy.**
- **Missing API credentials follow the same accumulate-and-report behavior.**

## What Was Fixed

The diagnostic checks correctly recognized an enabled but unavailable consultant
as unhealthy, but returned a non-zero status from inside the pipeline. Because
`doctor.sh` runs with `set -e`, that return terminated the entire command before
the human summary or JSON object could be produced.

This became visible in the clean Linux release runner after Grok Build became the
default Grok transport in v3.1.0: the runner had no `grok` executable, so
`doctor --json` emitted nothing.

CLI, switchable API-mode, and API-only checks now record the issue and continue.
The command still exits 1 after the completed summary when any issue exists.
