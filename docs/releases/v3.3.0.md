# Release v3.3.0

**Date:** 2026-07-29
**Type:** Minor — capability-based Grok and Kimi CLI compatibility
**Previous:** v3.2.0

## Highlights

- Grok and Kimi now prove CLI compatibility from the interface they actually need, not from a version string.
- Compatible future and vendor-custom CLI versions are accepted without a release-specific allowlist.
- Incomplete interfaces and missing requested models are rejected before a model request begins.
- Responses expose the observed CLI version as provenance alongside the capability-probe result.

## What's New

### Capability-based CLI compatibility

Before dispatch, the Grok adapter validates its complete headless argument
surface, strict sandbox controls, structured output, authentication state, and
the requested model. The probe runs inside an isolated environment and does not
send a consultation.

Kimi now validates prompt mode, `stream-json`, provider inventory, and the exact
configured model before dispatch. A CLI with a different version number remains
compatible when these capabilities are present; a CLI that cannot satisfy the
contract fails before a model call.

Grok's `--no-auto-update` flag remains optional. It is enabled when the installed
CLI advertises it and omitted otherwise, so a useful automation control does not
become an accidental version constraint.

### Diagnostic provenance

Successful Grok and Kimi CLI responses now include:

| Field | Meaning |
|---|---|
| `metadata.cli_version` | The version reported by the CLI, retained for diagnosis and provenance |
| `metadata.cli_compatibility` | `capability-probed` when the required interface passed |

These fields are additive. Existing response consumers and non-CLI transports
do not need to provide them.

## Breaking Changes

None — this release is backwards-compatible. No configuration changes are
required.

An installed Grok or Kimi CLI that lacks the adapter's required command,
structured-output, or requested-model surface will now be rejected before
dispatch instead of failing later during a consultation.

## Upgrade Guide

```bash
# npx (no install)
npx ai-consultants@latest "your question"

# git clone install
cd ~/.claude/skills/ai-consultants && git pull

# curl | bash install
curl -fsSL https://raw.githubusercontent.com/matteoscurati/ai-consultants/main/scripts/install.sh | bash
```

No configuration changes are required. If an adapter reports an incompatible
CLI, update that CLI and run `ai-consultants doctor` before retrying.
