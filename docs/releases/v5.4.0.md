# Release v5.4.0

**Date:** 2026-10-23
**Type:** Minor — Kimi K3.1 Pro in every Kimi tier, at max thinking effort
**Previous:** v5.3.2

## Highlights

- Kimi K3.1 Pro (released 2026-10-23) becomes the Kimi model in every tier,
  including `max_quality`, replacing K3 and K3-256k.
- Kimi now runs at max thinking effort on every consultation, whatever your
  own Kimi CLI settings say. `KIMI_REASONING_EFFORT` controls it.
- `configure` migrates the unpinned K3 values; pins and other aliases are kept.
- MiniMax-M3.1-Flash is unchanged: it has served every MiniMax tier since 5.3.0.

## What's New

### Kimi K3.1 Pro

| Tier | Before | Now |
|---|---|---|
| economy, standard, premium (default) | `kimi-code/k3` | `kimi-code/k3.1-pro` |
| maximum (`max_quality`) | `kimi-code/k3-256k` | `kimi-code/k3.1-pro` |

K3.1 Pro has a 1M-token context and always thinks; its efforts are `low`,
`high` and `max`. It needs a Kimi Code Plus plan or higher. The Kimi CLI must
list the alias: if `kimi provider list` does not show it yet, run `kimi` once
and `/login` to refresh the model list. Before any request, AI Consultants
checks that the alias is available to your account, so a missing model fails
fast instead of silently running another one.

### Thinking effort

The Kimi CLI has no effort flag. `KIMI_REASONING_EFFORT` (default `max`) is
validated like the other consultants' efforts and passed to the CLI as
`KIMI_MODEL_THINKING_EFFORT`, the CLI's documented override of the
`[thinking] effort` setting in `~/.kimi-code/config.toml`.

| `KIMI_REASONING_EFFORT` | Effect |
|---|---|
| unset | `max` |
| `low`, `high`, `max`, … | that effort |
| empty (`KIMI_REASONING_EFFORT=`) | the Kimi CLI's own setting |
| anything else | fails before any request |

### Costs

Moonshot has published no rate for K3.1 Pro, so it is catalogued as explicitly
unpriced: session reports disclose it instead of presenting it as free, and a
dollar budget cannot account for it. K3 rates stay in the catalog for pinned
models and past responses.

## Verification

All 35 suites, ShellCheck and the generated-doc check are green, locally and in
CI. New tests cover the tier catalog, the effort passed to the CLI (default,
explicit, empty and invalid), the `configure` migration and pins; they fail on
the previous code. One authorized live smoke (2026-10-23, no retry) returned a
structured answer with The Eastern Sage persona and confidence 10 in about
13.5 s, and Kimi's own session state recorded model `k3.1-pro` with thinking
effort `max`. Tokens for the Kimi CLI are estimated, since it reports no usage.
No model-quality benchmark is claimed.

## Breaking Changes

- The default Kimi model changes in every tier, and `max_quality` no longer
  uses `kimi-code/k3-256k`.
- Kimi now runs at `max` thinking effort by default, overriding the effort in
  your Kimi CLI config. Set `KIMI_REASONING_EFFORT=` (empty) to keep your own.
- On a Kimi Code plan below Plus, or before the CLI's model list includes
  K3.1 Pro, the Kimi consultant fails its capability check. To stay on K3,
  pin it with `npx ai-consultants configure --set KIMI_MODEL=kimi-code/k3`.

## Upgrade Guide

```bash
# npx (no install)
npx ai-consultants configure

# git clone install
cd ~/.claude/skills/ai-consultants && git pull && ./scripts/configure.sh

# curl | bash install
curl -fsSL https://raw.githubusercontent.com/matteoscurati/ai-consultants/main/scripts/install.sh | bash
```

`configure` moves an unpinned `KIMI_MODEL=kimi-code/k3` or
`kimi-code/k3-256k` to `kimi-code/k3.1-pro`. A pinned value
(`# ai-consultants:pin`), an environment override or another alias you set
yourself is kept. Credentials stay in the private user configuration.
