# Release v5.0.0

**Date:** 2026-09-01
**Type:** Major — auditable pre-flight coverage review with public modes
**Previous:** v4.0.4

## Highlights

- Coverage items now cite locally assigned source IDs, with an independent integrity verdict over omissions, inventions, duplicates, and non-normalizable responses.
- Three public modes make the intended workflows explicit: `fast-check`, `coverage-review`, and `max-coverage`.
- Host self-exclusion no longer silently shrinks presets; canonical fallbacks retain the effective target or fail clearly before dispatch.
- Atomic findings are never truncated. Any capped fallback context is disclosed in both JSON and the Markdown report.
- Mode, preset, alias, target, strategy, and default documentation is generated from one executable registry and checked for drift.

## What's New

### Auditable coverage integrity

Successful structured responses gain a compatible `response.findings[]` array. IDs are assigned locally as `<consultant-slug>:<index>`; provider-supplied IDs are discarded. Each synthesized `coverage` item must cite one or more of those IDs through `source_ids`.

The local post-check, not the synthesis model, publishes the verdict:

| Status | Meaning |
|---|---|
| `MET` | Every expected normalized source ID is represented exactly once over the documented audited fields. |
| `DEGRADED` | A source is missing or duplicated, fallback input is non-normalizable, or relevant fallback context was truncated. |
| `FAILED` | Attribution is structurally unusable or contains an invented source ID. |
| `NOT_APPLICABLE` | The selected strategy is not a coverage-union claim. |

Legacy synthesis and response fields remain available. This release verifies attribution-set integrity; it does not claim that natural-language paraphrases are semantically entailed by their cited findings.

### Explicit truncation

Normalized atomic findings are the primary attributable coverage input and are never clipped by `SYNTH_DETAIL_MAX_CHARS`. Usable fallback prose remains context-only. When it exceeds the configured Unicode-code-point limit, the artifact locally records:

- `coverage_input_truncated: true`
- `truncated_consultants: [...]`

The Markdown report renders the same disclosure. A truncated coverage input cannot receive `MET` or be presented as comprehensive.

### Public modes

| Mode | Preset | Default strategy | Intended use |
|---|---|---|---|
| `fast-check` | `fast` | `coverage` | Quick economy pre-flight check |
| `coverage-review` | `balanced` | `coverage` | General pre-flight coverage review |
| `max-coverage` | `max_quality` | `coverage` | Broadest eligible maximum-quality review |

`--mode` and `--preset` are mutually exclusive. An explicit `--strategy` overrides the mode default. Existing presets, the `max-quality` alias, strategies, custom agents, smart routing, and advanced configuration remain available.

### Host-aware preset capacity

Preset selection now applies self-exclusion first and fills the lost slot from statically configured canonical transports. If the effective target cannot be assembled, the command stops before provider dispatch with promised, selected, and missing counts. `max_quality` remains a ten-consultant catalog preset; a canonical invoking host has an attainable target of nine.

Fresh `init` scaffolding no longer forces `balanced`. Existing user configuration is not rewritten, and `coverage` remains the default strategy.

## Breaking Changes

- Explicit presets no longer continue with a silently undersized panel. Configure enough eligible transports or select a smaller preset/mode.
- Coverage-mode attribution is limited to locally normalized `summary`, `pros`, `cons`, `alternatives`, `caveats`, and `references`. Structured `detailed` text is not treated as audited evidence; fallback prose is manual-review context and degrades coverage integrity.

No command, preset, strategy, advanced configuration key, or legacy JSON field was removed.

## Upgrade Guide

```bash
# npx (no install)
npx ai-consultants --mode coverage-review "Review this change before I ship it"

# git clone install
cd ~/.claude/skills/ai-consultants && git pull

# curl | bash install
curl -fsSL https://raw.githubusercontent.com/matteoscurati/ai-consultants/main/scripts/install.sh | bash
```

No configuration migration is required. If an automation relied on a preset continuing with fewer consultants than advertised, choose a smaller mode or configure the missing transports. Consumers that previously treated every synthesis as comprehensive should gate that claim on `coverage_integrity.status == "MET"`.
