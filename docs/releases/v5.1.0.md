# Release v5.1.0

**Date:** 2026-09-09
**Type:** Minor — Fable and Astra defaults with stricter CLI completion and sandbox checks
**Previous:** v5.0.0

## Highlights

- Claude defaults to Fable 5.1; Codex defaults to Astra with high reasoning effort when none is configured.
- Claude response identity comes from content-bearing assistant events, with billing participants recorded separately.
- Codex separates JSON token telemetry from the final answer and rejects failed or unfinished turns.
- Grok checks incompatible runtime socket links before dispatch and refuses sandbox degradation without retry or API fallback.

## What's New

### Model defaults and configuration

| Tier | Claude | Codex |
|---|---|---|
| Default / premium / maximum | `claude-fable-5-1` | `gpt-6-astra` (implicit `high`) |
| Standard / medium | `claude-opus-5` | `gpt-5.6-terra` |
| Economy | `claude-haiku-4-5` | `gpt-5.6-luna` |

Sol remains selectable. During `configure`, exact unpinned persisted Codex defaults `gpt-5.5` and `gpt-5.6-sol` migrate directly to Astra with provenance. Pins, environment overrides and `--set` preserve explicit choices. Astra accepts valid explicit effort overrides; `none` and `minimal` fail before dispatch. Automatic effort does not leak into later tier selections.

### Transport and accounting

Claude requires a successful terminal stream result, preserving available token and provider-cost data on failures. Requested, content-reported and billing identities remain distinct. Codex CLI token totals come from JSON events; selecting a model with `-m` remains `requested-only`, not provider attestation.

Astra estimates use $10/M input and $50/M output. Above 272K input tokens, the full request uses twice the input rate and 1.5 times the output rate. Estimates exclude cache and service-tier adjustments and are not provider invoices.

Both Claude and Codex write JSON error envelopes when API-key validation fails before dispatch. Existing API implementations remain available, but API live acceptance is outside this release's explicitly selected CLI-only verification scope.

### Grok sandbox compatibility

Adapter and doctor share passive checks for symlinked runtime socket endpoints, including dangling and Docker Desktop links. The checks do not remove sockets or alter Docker settings. Sandbox refusal and non-application diagnostics fail even when the CLI exits zero; these failures cannot trigger retry or API fallback. Hidden mandatory flags such as `--no-memory` are validated through the native parser and remain present in real requests.

### Maintainer benchmark

The repository includes the preregistered Breadth v1 harness merged since v5.0.0. It remains excluded from npm. Its frozen roster, model/effort selections and preregistration are unchanged; this release makes no claim of a completed live benchmark or measured coverage gain.

## Breaking Changes

No response fields are removed. Model defaults and the associated estimated costs change. Unpinned historical defaults migrate during `configure`; use `# ai-consultants:pin` or explicit `--set` to retain them. Incomplete responses and unsafe Grok sandbox states now fail closed.

## Upgrade Guide

```bash
# Inspect configuration without starting a consultation
npx ai-consultants configure --show-parameters

# Existing repository installation
cd ~/.claude/skills/ai-consultants && git pull
```

Use an existing private configuration directory explicitly with `AI_CONSULTANTS_CONFIG_DIR=/absolute/private/config-directory`. Project `.env` files are not automatically discovered. CLI use relies on existing CLI authentication; no OpenAI API key is required for Codex CLI with ChatGPT login.
